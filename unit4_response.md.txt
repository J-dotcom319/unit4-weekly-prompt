## 1. When should you trap for exceptions?

Exception handling (trapping for exceptions) should be used whenever your program interacts with external resources or user input that could be unpredictable or malicious. This includes scenarios like reading from or writing to files (where the file might not exist or permissions might be denied), connecting to networks (where the connection might fail), or converting user input into specific data types (like converting a string to an integer). By trapping for these exceptions, you prevent your program from crashing abruptly. Instead of a "crash," you can provide a graceful error message, log the issue for debugging, or offer the user a chance to correct their input. It is a critical part of writing robust, user-friendly software that can handle real-world imperfections without failing catastrophically.

## 2. When storing data to a text file, containers, like the list ["red", "green", "blue"], lose their context. What are some options?

When complex data structures like lists or dictionaries are written to a text file as plain strings, they lose their type information and structure, making them difficult to read back into the program correctly. To solve this, you should use serialization formats that preserve data structure. The most common and safe option in Python is the `json` (JavaScript Object Notation) module. JSON allows you to dump Python data structures (like lists and dictionaries) into a formatted string that can be saved to a file and later loaded back into Python with all original types intact. Another option is the `pickle` module, which can serialize almost any Python object, though it is less secure for data coming from unknown sources. Alternatively, you could store data in a structured format like CSV (for tabular data) or use a database, but for simple Python objects, JSON is the standard best practice.

## 3. Why should you trap for specific exception types?

Trapping for specific exception types is crucial for maintaining the security and debuggability of your code. If you write a broad `except:` clause that catches *every* possible error, you might accidentally hide serious bugs, typos, or system-level failures (like a `KeyboardInterrupt` or `SystemExit`). For example, if you intend to catch a `ValueError` for bad user input but your code has a typo that causes a `NameError`, a broad exception handler would catch the `NameError` and suppress it, making it impossible for you to realize you made a mistake. By catching only the specific exceptions you expect (e.g., `except ValueError:`), you ensure that unexpected errors still crash the program, alerting you to real problems while allowing you to handle anticipated issues gracefully.

## 4. What kind of information are text files good for storing?

Text files are ideal for storing simple, unstructured, or human-readable information that does not require complex querying or high-security measures. They are perfect for logs, configuration settings, simple data exports, or storing content like stories and scripts where the primary goal is readability by humans or simple line-by-line processing. They are also useful for storing data that needs to be compatible with almost any system or programming language, as plain text is universally supported. However, they are **not** suitable for storing sensitive information (like passwords or credit card numbers) because they lack encryption, nor are they appropriate for complex, relational data that requires integrity checks, which should be stored in a database.

## 5. Describe refactoring and its benefits.

Refactoring is the process of restructuring existing computer code without changing its external behavior or functionality. The goal is to improve the internal structure, readability, and maintainability of the code. Benefits of refactoring include making the code easier to understand and modify in the future, reducing complexity, eliminating redundant code (which reduces the risk of bugs), and improving performance. It is a critical practice in professional software development, often summarized by the motto "make it work, then make it right." By regularly refactoring, developers ensure that their codebase remains healthy and sustainable over time, preventing "technical debt" from accumulating. In the context of this course, moving code into functions or classes (as we did with the Battery and Car classes) is a prime example of refactoring for better organization and reuse.
